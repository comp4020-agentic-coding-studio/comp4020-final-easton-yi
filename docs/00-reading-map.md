## 4. Important corrections to the previous PROCESS narrative

1. **"CLAUDE.md is still empty" is outdated.** The latest commit adds the process-logging harness. Earlier constraints came from INITIAL_PROMPT and later focused directives; their timing must remain distinct.
2. **"All later directives were committed before implementation" is unsupported.** The original Crit 9 test directive was not in the repository, and most later features and directives were committed together. The main text retains only the verified claim that the initial a46e7ed preceded the code.
3. **"This round is uncommitted" is outdated.** be91ad1 exists. A commit and a successful deployment are separate facts; retain the time boundary of the CI check and do not invent current production results.
4. **"Unchanged original text" can describe only the initial commit.** The current BRIEF and INITIAL_PROMPT contain later revisions, which are themselves evidence that the harness progressively absorbed lessons.
5. **Automation removes repeated coordination steps; it does not establish a measured percentage of time saved.** The original CRIT10 instructions and report support replacing repeated requests for the author to test individual changes with review of one report. They do not support an absolute absence of omissions. Stronger evidence is that self-review found defects in both the fixes and the report itself.
6. **A lower bound on architectural detail is not a competition over stick counts.** The main text describes recognisable geometry, layered recipes, cameras and multiple acceptance views. The 132-stick physics staircase validates that small component only, not the claim that giant static buildings obey player placement rules.
7. **Historical status documents are not synchronised.** The island section of process-log still says uncommitted, while the world status page and README also contain older deployment statements. Historical paragraphs cannot be treated as current release facts; use explicit commit boundaries.
8. **The updated visual judgement has an identified source.** The original report says the author had not reviewed the visuals; the author has now said that the world is close to the intended outcome. The main text uses only that retrospective opinion, without expanding it into acceptance of every night view, low-end device or detail.
9. **Open issues have not disappeared.** Original evidence still records some unmet Medium/Low budgets, GPU-process growth, portal-lettering contrast, some safe-point/opening issues, and outstanding physical-phone and real-GPU checks. Within the word limit, the main text keeps the central limits and links to the full records.

## 5. Why the main text is allocated this way

The four sections cover: (1) the idea becoming a contract and stack choice; (2) performance and the autonomous verification-and-repair cycle; (3) the abstract world becoming components, recipes and resource constraints; and (4) interaction and day/night corrections becoming rules for later work. The third section receives more space because it most clearly demonstrates the author's distinctive design direction and the handover from GPT-assisted planning to the coding agent. The ending uses the evidenced rejection of turn-taking/table locking in ADR-0006 to return the final trade-off to the multiplayer theme.

These are evidence-based editorial choices, not newly discovered claims about the author's thoughts. The main text retains its assisted retrospective draft notice. Before submission, the author should confirm the first-person statements and the scope of their judgement of the world, and complete the sources and position in the README.
