== How the product handles a failed landmark (src/client/world/WorldView.ts)
Far files stream nearest first, two at a time (updateStreaming). A failed far file is retried after 1 s and 2 s;
the third failure sets it to 'error' and raises the notice '<title> couldn't load. The rest of the island is still
here.' (loadFar .catch). Each other far file that finishes calls updateStreaming, which starts the next one; the
error doesn't stop them. L03 is near home, so it is requested early and its notice comes about 2 s after load.

== Cause: test synchronisation, not a fallback defect

== Fix (tests/e2e/world-protection.spec.ts only)

them, that L03 was requested exactly 3 times (failed for good), and that the island is usable: Start exploring is
enabled and puts the world into exploring, after which L03 is still not requested again or ready.
